# Benchmark baseline

Generated by `npm run perf:bench:baseline`. **These are one machine's numbers, not a threshold.** They are portable as ratios and curve shapes, not as absolute milliseconds. See `tests/perf/README.md`.

| | |
|---|---|
| Measured | 2026-09-29 |
| CPU | Apple M1 Max (10 threads) |
| Arch | darwin/arm64 |
| Node | v26.8.1 |
| Memory | 32 GB |

`text-layout.bench.ts` was re-measured alone on 2026-10-19, on the same node (studio: Apple M1 Max, 10 threads, 32 GB, Node v26.8.1), after it stopped timing glyph grouping. `tessellate.bench.ts`, run beside it that day, came out about 40% slower than its row here, so compare the text-layout rows with each other, not with the other sections.

`hit-test.bench.ts` was re-measured alone on 2026-10-22 on keiei (Apple M2, 8 threads, 24 GB, Node v26.8.2; studio could not grant a solo run), after `hitTestArea` moved onto the BVH pick index, so compare its rows with each other, not with the other sections. Its raw results are in `tests/perf/recorded/pick-index-2026-10-22/`. The before-number for the index is each group's own "full walk" row, measured in the same run, not the 2026-09-29 rows this section replaced: the unindexed walk had already slowed from 3.04 ms (9db2cae5f) to 8.97 ms (394b86d43, the branch base) on the 25% marquee at 10,000 nodes, timed on keiei in one session (`across-commits/` there; filed in `docs/TODO.md`).

`median` is the number to compare — the mutating and allocation-heavy benchmarks take periodic GC pauses that inflate the mean by an order of magnitude without the code having changed. `rme` is the relative margin of error on the mean; a large one means read the median and ignore the mean entirely.
