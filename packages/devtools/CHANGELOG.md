# @weasel-js/devtools

## 2.0.0

### Major Changes

- 7158bf0: A `get-history` request asks for the stacks' entries with `historyEntries`, and the slice returns them under that name; both were `checkpoints`.
  
  The panel's switch reads "entries".
  
  ```ts
  // before
  client.request(rootId, { type: 'get-history', cursor, checkpoints: true });
  // after
  client.request(rootId, { type: 'get-history', cursor, historyEntries: true });
  ```
  
  <!-- entry: breaking api -->
- 5dba94f: `<RegistryBrowser>` reports a new pick through `onSelectionChange`, as the kit's other components holding a selection do; the prop was `onSelect`.
  
  ```tsx
  // before
  <RegistryBrowser categories={categories} selected={pick} onSelect={setPick} detail={detail} />
  // after
  <RegistryBrowser categories={categories} selected={pick} onSelectionChange={setPick} detail={detail} />
  ```
  
  <!-- entry: breaking api -->

### Minor Changes

- 9a3bf41: `@weasel-js/devtools/hook` puts a page's canvases in a panel's view, and `@weasel-js/devtools/protocol` carries the messages between them.
  
  `devtools` is a contribution: every canvas below `<AmbientContributionsProvider contributions={[devtools]}>`, or one given `ambient={[devtools]}`, registers with the hook on `window.__weaselDevtools__`, which the first installs. `/hook` also has `attachDevtools`, `installDevtoolsHook`, `createDevtoolsHook` and `createDevtoolsRoot`. `/protocol` has the message types and guards, the in-page and window transports, and `serialize`, and loads neither React nor core, so an extension's background and content scripts import it.
  
  <!-- entry: rank=8 new api -->
- 0315cdb: The page's devtools session refuses a posted message that is not a protocol message, and `isPanelMessage` and `isPageMessage` tell one apart.
  
  A request of the wrong shape is answered with an `error` naming its type; a value that is not an object is ignored. Both are exported from `@weasel-js/devtools/protocol`.
  
  <!-- entry: api fix -->
- 757101c: `@weasel-js/devtools/mount` gives canvases devtools in development without loading the hook in a production bundle.
  
  `lazyDevtools` is the `devtools` contribution behind a dynamic import of the hook. `DEV_DEVTOOLS` is `[lazyDevtools]` when `isDev()` holds and `[]` otherwise, for an app's provider over bare canvases. `devtoolsOff` withholds devtools from every canvas and shell below where it is provided. `ShellDevtools` is the wrapper `<Lab>`, `EditorShell` and forge's frames use.
  
  ```tsx
  import { AmbientContributionsProvider } from '@weasel-js/core';
  import { DEV_DEVTOOLS, devtoolsOff } from '@weasel-js/devtools/mount';
  
  <AmbientContributionsProvider contributions={DEV_DEVTOOLS}><BareCanvases /></AmbientContributionsProvider>;
  <AmbientContributionsProvider contributions={[devtoolsOff]}><AppWithShells /></AmbientContributionsProvider>;
  ```
  
  <!-- entry: rank=8 new api -->
- 5dec30c: The Dispatch tab's outcome filters sweep: a drag from one across the other sets both to what the press set the first.
  
  <!-- entry: new behavior -->
- a3a9fd1: The State tab's overlay switches show one overlay alone on Alt-click, and a drag across them sets each one it crosses.
  
  A second Alt-click shows every overlay again.
  
  <!-- entry: new behavior -->
- 1b0a5fc: Two devtools panels sharing a channel to a page no longer read each other's answers; the earlier one says the later replaced it.
  
  A `yo` and a `bye` may carry a `session`, which `createDevtoolsClient` sets fresh on each open, and the page tags every message it sends that connection with it. A `bye` naming another session closes nothing. The client ignores messages tagged for another session, and goes to `error`, rejecting its pending requests, on hearing another session's `sup`. Messages without a `session` work as before.
  
  <!-- entry: fix api -->
- 0e26f75: `TraceRead.coordCursor` says where a trace follower's coord records stand after the `coords` it returns.
  
  It is to `coords` what `cursor` is to `entries`, so a reader can key each record by its place in the canvas's ring.
  
  <!-- entry: api -->

## 1.13.0

### Patch Changes

- 6bb74c2: **Breaking.** Four props now decide how a component looks, and each is a hint the component draws from as it sees fit: `stance` (the angle it comes from), `grade` (how serious), `emphasis` (how loud), and `tint` (an exact color). They replace a prop that meant two things and four spellings of severity. Color resolves as tint, then grade, then stance; emphasis sets how loudly it shows. Stance and emphasis pass to everything inside a surface; grade and tint do not, so a `danger` dialog's Cancel button stays plain.
  
  | Was | Now |
  |---|---|
  | `status="accent"` / `"muted"` / `"neutral"` | `emphasis="high"` / `"low"` / nothing |
  | `status="success"`, `"warn"`, `"danger"`, `"info"` | `grade="…"` |
  | Badge `status="custom"` with `--badge-edge` | `tint={…}` |
  | `tone={…}` (palette index or color), KeyDiagram's per-key `tone` | `tint={…}` |
  | `stance="scope"` | `stance="clarify"` |
  | `stance="danger"` / `"notice"` / `"important"` | `grade="danger"` / `grade="warn"` / `emphasis="high"` |
  | Button `variant="primary"` / `"secondary"` | `stance="confirm"` / the default `variant="solid"` |
  | Toast `tone: 'warning' \| 'error'`, `toast.warning`, `toast.error` | `grade: 'warn' \| 'danger'`, `toast.warn`, `toast.danger` |
  | labkit Toolbar `variant="danger"` | `grade="danger"` |
  
  New stances are `confirm` and `cancel`. `useStance`, `StanceProps` and the `@weasel-js/ui/stance` subpath are gone; use `useAppearance`, `AppearanceProps` and `@weasel-js/ui/appearance`. `BadgeStatus`, `CodeStatus`, `ButtonStatus`, `DetailRowStatus` and `ToastTone` are deleted; `Grade`, `Emphasis` and `Stance` are exported in their place, and `DetailRow`, labkit `Readout` and Toast take `grade`. `BADGE_STATUS_ICONS` is now `GRADE_ICONS` and `EMPHASIS_ICONS`, exported from `@weasel-js/ui` and `@weasel-js/ui/appearance`, and the status glyphs are `gradeSuccess`, `emphasisHigh` and `emphasisLow`.
  
  In `@weasel-js/theme`: `GRADES`, `GRADE_TOKENS`, `EMPHASES`, `EMPHASIS_FG`, `EMPHASIS_SLOTS` and `GRADE_SLOTS` join `STANCES`. `TONE_REF` is `TINT_REF` (`{ ref: 'tint' }`), the theme's tone list is its tint list (`ThemeProvider tints`, `useTints`, a theme's `"tints"`), and hud's `tones` option is `tints`. Stance tokens are renamed: `--wzl-stance-scope-*` → `--wzl-stance-clarify-*`, `--wzl-stance-<s>-tone(-mix)` → `-tint(-mix)`, `--wzl-panel-tone-mix` → `--wzl-panel-tint-mix`, `--wzl-button-primary-*` → `--wzl-button-confirm-*`; the danger, notice and important stance tokens are removed. ## 1.13.0-rc.0

### Patch Changes

- 6bb74c2: **Breaking.** Four props now decide how a component looks, and each is a hint the component draws from as it sees fit: `stance` (the angle it comes from), `grade` (how serious), `emphasis` (how loud), and `tint` (an exact color). They replace a prop that meant two things and four spellings of severity. Color resolves as tint, then grade, then stance; emphasis sets how loudly it shows. Stance and emphasis pass to everything inside a surface; grade and tint do not, so a `danger` dialog's Cancel button stays plain.
  
  | Was | Now |
  |---|---|
  | `status="accent"` / `"muted"` / `"neutral"` | `emphasis="high"` / `"low"` / nothing |
  | `status="success"`, `"warn"`, `"danger"`, `"info"` | `grade="…"` |
  | Badge `status="custom"` with `--badge-edge` | `tint={…}` |
  | `tone={…}` (palette index or color), KeyDiagram's per-key `tone` | `tint={…}` |
  | `stance="scope"` | `stance="clarify"` |
  | `stance="danger"` / `"notice"` / `"important"` | `grade="danger"` / `grade="warn"` / `emphasis="high"` |
  | Button `variant="primary"` / `"secondary"` | `stance="confirm"` / the default `variant="solid"` |
  | Toast `tone: 'warning' \| 'error'`, `toast.warning`, `toast.error` | `grade: 'warn' \| 'danger'`, `toast.warn`, `toast.danger` |
  | labkit Toolbar `variant="danger"` | `grade="danger"` |
  
  New stances are `confirm` and `cancel`. `useStance`, `StanceProps` and the `@weasel-js/ui/stance` subpath are gone; use `useAppearance`, `AppearanceProps` and `@weasel-js/ui/appearance`. `BadgeStatus`, `CodeStatus`, `ButtonStatus`, `DetailRowStatus` and `ToastTone` are deleted; `Grade`, `Emphasis` and `Stance` are exported in their place, and `DetailRow`, labkit `Readout` and Toast take `grade`. `BADGE_STATUS_ICONS` is now `GRADE_ICONS` and `EMPHASIS_ICONS`, exported from `@weasel-js/ui` and `@weasel-js/ui/appearance`, and the status glyphs are `gradeSuccess`, `emphasisHigh` and `emphasisLow`.
