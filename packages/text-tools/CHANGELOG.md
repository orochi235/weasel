# @weasel-js/text-tools

## 2.0.0

### Major Changes

- 744fbce: The path, text, rig, diagram and measure actions act on the `operands` dep, the selection by default.
  
  This is breaking for code that runs these actions with deps it builds by hand: each now declares `operands` in `requires` and reads it where it read `selection`, as core's editing actions do. On a `<SceneCanvas>` nothing changes, since `operands` answers with the selection unless a host sources its own. Selecting actions (diagram's edge pick and sequence-part pick, following an off-page tag) still read `selection`.
  
  ```ts
  // before
  snipAtCrossingsAction.invoker.run({ scene, selection, applyOps });
  // after
  snipAtCrossingsAction.invoker.run({ scene, operands: selection, applyOps });
  ```
  
  <!-- entry: rank=0 breaking api -->
- 72544b9: `drawOneEditing` is `drawOneWithoutEditedText`: it draws every node but drops the edited node's text.
  
  ```ts
  // before
  const drawOne = drawOneEditing(editingId);
  // after
  const drawOne = drawOneWithoutEditedText(editingId);
  ```
  
  <!-- entry: breaking api -->
- 0cc203a: `WHITEBOARD_TOOLS` is gone; it held exactly `TEXT_TOOLS`' tools, so pass `TEXT_TOOLS`.
  
  ```tsx
  // before
  <SceneCanvas defaultTools={[WHITEBOARD_TOOLS]} … />
  // after
  <SceneCanvas defaultTools={[TEXT_TOOLS]} … />
  ```
  
  <!-- entry: breaking api -->
- 86019a4: `editTextAtAction` is `enterTextEditAtAction`, with the id `enterTextEditAt`, beside its sibling `enterTextEdit`.
  
  Its double-click binding's id is `enterTextEditAt.doubleClick`.
  
  ```ts
  // before
  actions.trigger('editTextAt', { world });
  // after
  actions.trigger('enterTextEditAt', { world });
  ```
  
  <!-- entry: breaking api -->
- 4bee28f: Text-tools' presets move off the main entry to `@weasel-js/text-tools/presets`, as `text`, `textTools` and `whiteboard`.
  
  `textPreset`, `textToolsPreset` and `whiteboardPreset` are gone from the main entry; `createTextPreset` and `createTextToolsPreset` stay on the main entry.
  
  ```tsx
  // before
  import { textPreset, textToolsPreset } from '@weasel-js/text-tools';
  <SceneCanvas features={[drawPreset, textPreset, textToolsPreset]} />;
  
  // after
  import * as textTools from '@weasel-js/text-tools/presets';
  <SceneCanvas features={[presets.draw, textTools.text, textTools.textTools]} />;
  ```
  
  <!-- entry: rank=10 breaking api -->
- 50cf32b: `TEXT_TOOLS` has the id `'text'`, and the text and sticky tools sit in the `text` palette group, matching the `tools:text` preset.
  
  Both were `'type'`, and the set's label is "Text".
  
  ```tsx
  // before
  <ToolPalette tools={tools} groupOrder={['select', 'view', 'shape', 'type']} />
  // after
  <ToolPalette tools={tools} groupOrder={['select', 'view', 'shape', 'text']} />
  ```
  
  <!-- entry: breaking api -->

### Minor Changes

- fd2cbc8: Core no longer paints, routes, inserts or edits text; a canvas turns text on with `@weasel-js/text-tools`' `textTools.text`.
  
  This is breaking. `kit:text` is no longer a built-in painter, `inferredNodeRouting` has no `'text'`, `defaultNodeProperties` and `inferredNodeProperties` carry no text kind, the `insert` dep builds no `text` or `sticky` node, and no canvas mounts a text editor of its own. `textTools.text` brings all of them back, with `enterTextEdit`, `enterTextEditAt` (a double-click opening text in place) and `editEffectText`. A scene drawn with no canvas paints text once its painter is registered.
  
  ```tsx
  import { TEXT_PAINTER } from '@weasel-js/text-tools';
  import * as textTools from '@weasel-js/text-tools/presets';
  
  <SceneCanvas features={[presets.draw, textTools.text]} scene={scene} />;
  nodeShapesOf(scene).register(TEXT_PAINTER); // for renderSceneToPixels, an export
  ```
  
  `textBoxOf`, `TextNodeData`, `TextOverflow`, `textFrameOf`, `edgeColor`, `TextEdge`, `TextFrame`, `TextShadow`, `useSceneTextEdit`, `UseSceneTextEditOptions`, `UseSceneTextEditReturn`, `DefaultTextData`, `textEditJoin`, `EditingDrawOne`, `createTextLayer`, `enterTextEditAction` and `enterTextEditAtAction` are imported from `@weasel-js/text-tools`.
  
  <!-- entry: rank=20 breaking api pick -->
- 3a8b706: A blurred drop shadow fills its interior with its full color, as an unblurred one does. This holds for HUD box shadows and text shadows too, on canvas and in SVG export.
  
  `dropShadowLayers` returns `alphas`, the opacity of each path, and `TextFrame.shadow` carries the same; the single `alpha` and `opacity` they replace are deprecated.
  
  <!-- entry: fix visual api deprecates -->
- 6a06f54: `startEdit` takes `caret: 'end'`, which opens an edit with the caret after the last character of the text the editor shows.
  
  <!-- entry: api -->
- `editEffectText` is registered by `textTools.text` alone, not by path-tools' `pathTools.pathEdit`.
  
  A canvas opens curved text from path edit when it runs both.
  
  <!-- entry: api -->

### Patch Changes

- 21d7e6b: A canvas inside a `useSceneTextEdit` container of another scene keeps its own text editor, so a double-click there opens text.
  
  <!-- entry: fix -->
- ff7314a: While the canvas's own text editor has a node open, a second canvas of the same scene beside it keeps drawing that node's text.
  
  <!-- entry: fix -->
- 7f1cc2d: Converting a text node with `overflow: 'clip'` to outlines keeps only the glyphs inside its box, cut at the box edge, as the node draws them.
  
  <!-- entry: fix -->
- 471581b: Packages no longer install weasel siblings their code never uses.
  
  `@weasel-js/editor` stops asking for `@weasel-js/geom` as a peer and takes `@weasel-js/editing` only as one; `@weasel-js/prefs-editor` drops `@weasel-js/paint-kinds`, `@weasel-js/ui` drops `@weasel-js/storage`, `@weasel-js/icons-plugin` drops `@weasel-js/icons`, `@weasel-js/labkit` drops `@weasel-js/animator`, `@weasel-js/measure` drops `@weasel-js/theme`, `@weasel-js/rig` drops `@weasel-js/history` and `@weasel-js/renderer`, `@weasel-js/text-tools` drops `@weasel-js/icons` and `@weasel-js/prefs-schema`, and `@weasel-js/ui-canvas` drops `@weasel-js/history`.
  
  <!-- entry: internal -->
- f9b150c: A click on a text-on-path effect opens its text with the caret at the end, also in an editor with a custom `getText`.
  
  <!-- entry: fix -->
- fd6c009: Converting a rotated text node with `overflow: 'clip'` to outlines cuts its glyphs at the rotated box's edge.
  
  <!-- entry: fix -->
- cfebac4: A `fit: 'shrink'` text node painted before its font loaded is refitted once the face arrives.
  
  <!-- entry: fix visual -->
- 4069e86: With the sticky tool, a click on a selected shape that is not text, or on one of several selected nodes, places a note as it does elsewhere.
  
  <!-- entry: fix -->
- 201717b: The sticky tool given a `background` or `fill` with no `paint` makes notes with no paper, or no ink, instead of the default yellow and ink.
  
  <!-- entry: fix -->
- 42af0bf: Text laid along a path wraps in the box its node's `padding` insets, as the node itself draws, so its first line holds the same words.
  
  <!-- entry: fix visual -->
- 6fb8869: Double-clicking text sized in `{ px }` on a zoomed canvas opens the edit with the caret at the character clicked.
  
  <!-- entry: fix -->
- a0d5f84: `textClusters` takes a `height`, so a shrink-fitted text node on a path effect lays its glyphs at the size it draws at.
  
  Without a `height`, a shrink-fitted node shrinks to its `width` alone.
  
  <!-- entry: fix api visual -->
- e970fad: Text laid along a path effect warns in development, once per font family, when that family can give no outlines.
  
  A failed load of its outlines warns too.
  
  <!-- entry: fix -->
- bce203a: Editing a styled text node's Text in the properties panel shows the new text, keeping the styling of the characters left as they were.
  
  <!-- entry: fix -->
- cea89d2: A stroke set on part of a text node's text counts toward its drawn bounds and pick reach, so it is not culled at the box edge.
  
  <!-- entry: fix -->
- 62aede0: An install that nests `@weasel-js/geom` under text-tools now resolves `polygon-clipping`, which text-tools depends on.
  
  geom's `./booleans` loads it, and geom lists it only as an optional peer.
  
  <!-- entry: fix -->
- e3a1721: Installing @weasel-js/text-tools no longer brings in the prefs store: it depends on @weasel-js/prefs-schema.
