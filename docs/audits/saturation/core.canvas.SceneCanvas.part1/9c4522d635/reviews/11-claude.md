## Two presets that refine each other crash any keyed merge with a TypeError instead of a usable error
- where: packages/core/src/canvas/SceneCanvas/presetMerge.ts:46 (mergeByKey), reached from features.ts:268 (resolveFeatures → layers / oneOf) and presetOwnTools
- scenario: preset A has `refines: ['b']` and preset B has `refines: ['a']`, and both give the same layer slot, tool id, chrome rule, `selection` or `selectionChrome` with different values. `place` in resolveFeatures records both edges (A→B while placing A, then B→A while placing B), so `refinesRelation` answers true both ways. The conflict check passes because each "refines" the other. It should either throw the "[SceneCanvas] presets … both give …" error or reject the refinement cycle by name.
- evidence: read (traced resolveFeatures.place and refinesRelation by hand; not run)
- severity: low
