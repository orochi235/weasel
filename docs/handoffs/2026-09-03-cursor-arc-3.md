# Cursor arc 3 — the painted tier

For whoever picks up the next arc of `@weasel-js/cursor`. Assumes you have read
`docs/superpowers/specs/2026-09-03-cursor-system-design.md`; this only carries
what that spec and `docs/TODO.md` cannot.

Arcs 1 and 2 are merged to `main`. Arc 3 is `paint.ts`, the canvas layer, the
escalation rule and the `cursor: none` handoff, shipping `brush` with a
world-space radius.

## Conventions arc 2 set that the painter must honour

**`resize` is horizontal at angle 0**, so a baked angle is the direction the
resize axis runs. `cornerResize` adds ±π/4 for the corner diagonal plus the
target's rotation; `rotationHandle` passes the target rotation alone.

**Rotation happens in a viewBox that does not grow.** `bakeCursor` wraps the
paths in `<g transform="rotate(…)">` about the box centre, so a rotatable glyph
must fit the inscribed circle — `rotationFitsInBox` is the guard, and
`glyphs.test.ts` runs it over the rotatable set. The painter rotates the same
record rather than a rotated `d`, which is why the transform is on the group and
not baked into the path data.

**The cache keys on the quantized step, not the raw angle.** The hover pump
feeds a continuously varying selection rotation; a raw-angle key never hits.

## `npm run proof:pixels` is the check that matters for a new glyph

The 11× sheet (`proof:cursors`) cannot stand in for it, and this is not a
theoretical worry: the first `rotate` draft lost both arrowheads at true cursor
size while looking correct at 11×, and the second — heads enlarged to compensate
— turned them into blunt slabs that had stopped being arrows. Rasterize at the
device pixels the cursor actually gets before believing any glyph is done.
`ANGLES=0,0.3927,… npm run proof:pixels -- <names>` checks rotated bakes on the
same grid.

`rotate` reads at 24×1 and at both 2× grids. At 16×1 it degrades to a hook —
16 device pixels is not enough for an arc plus two heads. Nothing requests 16
today (`bakeCursor` defaults to 24); if arc 3 gives a consumer a reason to, that
glyph needs a different drawing, not a thicker one.
