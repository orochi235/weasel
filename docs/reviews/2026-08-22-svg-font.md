# Review: `@weasel-js/svg` and `@weasel-js/font`

A correctness pass over SVG import/export and font loading, for anyone
touching either package next. It says what was wrong, what changed, and what
was left alone on purpose. Every finding below was reproduced with a test
before it was fixed; every fix was mutation-checked by breaking it and
confirming the test failed.

## What was wrong

**Paint servers were only found under `<defs>`.** `collectGradients` and
`collectPatterns` walked the direct children of `<defs>` and nothing else, so
a gradient declared anywhere else — legal SVG, and what several authoring
tools emit — resolved to "unknown gradient" and the fill fell back to black.
`IGNORED_TAGS` also listed the gradient tags in camelCase while matching a
lowercased tag name, so the same file collected a spurious "unsupported
element" warning.

**Gradient `href` inheritance was ignored.** A gradient that takes its stops
from another (`<linearGradient id="g" xlink:href="#base" …/>`) resolved with
zero stops and painted nothing. Attributes and stops now both follow the
chain, with a cycle guard. `gradientTransform` was dropped in silence; it now
warns. Percentages were read as bare numbers, so `x2="100%"` became 100 bounds
units and `stop-opacity="50%"` became opaque.

**A leaf's `transform` was composed against the wrong frame.** Geometry is
baked through the inherited matrix at parse time, but the element's own
transform was decomposed against the *baked* bounds — two different coordinate
spaces. A rotation inside a translated `<g>` therefore failed to decompose,
and the fallback baked the local matrix into world geometry, moving the shape
as well as losing the rotation. Both steps now use `ctm · local · ctm⁻¹`.

**Any stroke with `stroke-opacity` re-serialized to invalid XML.**
`SvgStroke.opacity` and its paint's `opacity` are two models of one SVG
attribute and parse fills in both, so the serializer wrote the attribute
twice. No XML parser accepts that, so the whole document failed to reload.

**The computed `viewBox` ignored rotation and group transforms**, cropping
rotated content out of an export that did not supply its own `viewBox`.

**`<text>` ignored SVG's whitespace rules.** Importing any pretty-printed file
pulled the source indentation into the document text, and — because the height
estimate counts newlines — reported a one-line label as four lines tall.

**A nested `<svg x= y=>` establishes a viewport at that origin**; its children
were placed as if it sat at 0,0.

**In the shared `d=` grammar** (`pathFromD`, in `@weasel-js/core`): the
tokenizer split argument runs on any letter, so the `e` of an exponent read as
a command and `d="M1e2 1e2"` produced an empty path. Arc flags are single
`0`/`1` digits needing no separator, so the legal `A5 5 0 0110 0` read four
arguments short and the arc was dropped entirely.

**Installed faces collided on one variant slot.** `enableLocalFontOutlines`
maps a style string onto a (weight, style) pair, and "Helvetica Neue Condensed
Bold" lands on 700/normal exactly like "Helvetica Neue Bold". Whichever
`queryLocalFonts` returned last won, so large text could paint condensed
glyphs at the upright face's advances.

Smaller: `opacity` was read as a presentation attribute only, missing
`style="opacity:…"`; root `width` / `height` silently dropped a unit suffix
(`100mm` → 100).

## What changed

Five commits, one per theme. New coverage lives in
`packages/svg/src/gradients.test.ts`, `document.test.ts` and
`roundtrip-property.test.ts`, plus additions to `path-commands.test.ts` and
`outline/localFonts.test.ts`.

`roundtrip-property.test.ts` is the one worth keeping in mind: it asserts that
once a tree has been through parse → serialize, going round again is
byte-identical, over forty seeded trees of paths, text, images, groups,
gradients, strokes, rotation and opacity. The first pass is excluded because
parsing is lossy by design (a group's `transform` collapses onto its
descendants); everything after it has to be a fixed point. It found the
transform-composition bug and the duplicate `stroke-opacity`, neither of which
the example-based tests had reached.

**Exported SVG bytes change.** `<text>` gains `xml:space="preserve"`, a stroke
writes `stroke-opacity` once, and a document with rotated or group-transformed
content gets a larger computed `viewBox`. Visual baselines were not run (they
bind fixed ports and other agents were working concurrently).

One change is outside the reviewed packages: the `d=` grammar fixes are in
`packages/core/src/features/paths/pathFromD.ts`, because that is where the
grammar lives and `parseSvg` lowers every `<path>` through it. Its coverage is
in `@weasel-js/svg`, next to the rest of the path-command tests.

## Deliberately not fixed

**Percentages on a `userSpaceOnUse` gradient.** They are now read as ratios,
which is right for `objectBoundingBox` (the default, and the common case) and
wrong for user space, where a percentage is relative to the viewport. The
parser tracks no viewport to resolve it against, and the previous behavior —
reading `100%` as the number 100 — was wrong in both cases.

**`fill="none"` on `<text>` becomes black.** `TextStyle.fill` has no "paint
nothing" value, so the information has nowhere to land. Fixing it means a
change to the kit's text model, not to this package.

**A nested `<svg viewBox>` is not rescaled.** Implementing it means the full
`preserveAspectRatio` fitting algorithm plus clipping, neither of which the
node model expresses. It now warns instead of placing geometry silently wrong.

**`<use>`, `<clipPath>`, `<symbol>`, `<mask>`, `<filter>`** are still
unsupported and still warn. Each is a feature, not a bug.

**`.dfont` and `cmap` format 6.** `.dfont` is detected and declines by name;
nothing in the tree claims to read a Macintosh resource map, and nothing
should start. Helvetica's `cmap` format 6 defeats opentype.js, so
`glyphOutline` returns `null` for it and the face falls back to the SDF tier —
which is the ladder working. Neither was papered over.

**Dynamic-atlas page patches accumulate without bound.**
`syncDynamicPageTexture` walks every patch a page has ever recorded and skips
the ones already uploaded, so the scan grows with the number of glyphs baked.
It is a per-frame cost with no correctness consequence, and trimming it needs
a policy for how long a patch has to outlive the slowest cache. Left as a
note, not a change.

## Not verified

The whitespace change alters `<text>` bytes and the `viewBox` change alters
document extents, so rendered output could move. `npm run test:visual` was off
limits for this pass (fixed ports, concurrent agents), so nothing here is
backed by a pixel comparison — `test:kit` and the `weasel-ui` project (which
is where the `svg` and `font` suites actually run; `test:kit` does not include
them) are green.
