# Review: `@weasel-js/ui` and `@weasel-js/hud`

A correctness, accessibility, and API-consistency pass over `packages/ui/` and
`packages/hud/`, for whoever maintains those two packages. It says what was
broken, what landed, what was found and deliberately left, and what could not
be checked from here.

Every fix below carries a test that fails without it (verified by reverting the
fix and re-running). Gates run: `tsc --noEmit`, `npm run lint`, `npm run
test:ui` (1518 tests), `npm run test:stories` (267). The visual, perf, and e2e
suites were not run — they bind fixed ports and other work was in flight.

## Fixed

**Controlled `null` reads as uncontrolled.** `Select` and `ComboBox` passed
`selectedKey ?? undefined` to React Aria, and React Aria decides controlled vs
uncontrolled on `value !== undefined`. Setting `selectedKey={null}` to clear a
selection therefore dropped the component into uncontrolled mode: the previous
value stayed on screen and a "changed from controlled to uncontrolled" warning
appeared. `SelectionPanel` passes exactly that for a mixed enum property, so
the panel could not show "Mixed".

**`DataGrid` reorder reported one index for every drop.** `useReorderDragList`
finds the target row by walking the container's `children`; the ref was on the
wrapper `<div>`, whose only child is the `<table>`. The ref moved to `<tbody>`.
While there: sortable headers were `<th onClick>` — not focusable, no
`aria-sort` — and are now buttons inside a `th` that carries the sort state;
the absolutely-positioned drop indicator, offset by a hard-coded 28px per row
against rows that are not 28px tall, became a class on the target row.

**A locked row was a ceiling, not a wall.** `useReorderDragList` clamped every
drop to the index of the *first* locked row, so a row below a locked one could
be dropped above it — the opposite of the documented "cannot be crossed". The
clamp is now the run between the nearest locked rows either side of the grabbed
row, and a multi-selection spanning a wall drops the members on the far side.

**`Slider`: keyboard bypassed `constraint: 'ordered'`.** Drags clamped a thumb
to its neighbors; arrows, Page keys, Home and End did not. End sent a thumb
straight past the one above it.

**`Slider` and `BandEditor`: drags that never ended.** Both attach
`pointermove`/`pointerup` to `document` and remove them only in `pointerup`. A
`pointercancel` — a touch drag the browser takes over, a system gesture — never
fires `pointerup`, so the listeners stayed and the thumb or seam tracked a
released pointer indefinitely. Unmounting mid-drag left them attached too. Both
now handle `pointercancel` and tear down on unmount, the way `ResizeHandle` and
`LayeredCurveEditor` already did.

**`Slider` thumbs were unreachable by pointer users.** `onPointerDown` calls
`preventDefault()`, which suppresses the focus a press would give the thumb —
and the arrow keys are bound to the thumb. Clicking a thumb then pressing an
arrow did nothing. The handler now focuses the thumb explicitly.

**`BandEditor` swallowed `x` from anywhere inside it.** The merge shortcut
matched on `e.key` alone, with no target and no modifier check: typing `x` into
a control a consumer put in `renderBand`, or pressing Cmd+X to cut, deleted a
band. It now ignores modified keystrokes and keystrokes from text entry. Its
seams also gained Home/End and the vertical arrow aliases `role="slider"`
implies.

**`GradientHandles` committed the wrong position.** The ref holding the last
drag point was seeded once at mount and only refreshed on move, while `onEnd`
fired on every pointerup. Clicking a handle without moving it committed the
mount-time screen position — so after a pan, or after the value changed from
another control, a bare click yanked the gradient back. A `pointercancel` also
committed wherever the abandoned drag stopped. A press that never moves now
writes nothing, a cancel restores the live preview, and the handles respond to
the arrow keys. `role="slider"` became `role="button"`: the role requires an
`aria-valuenow`, and a 2-D handle has no single value to put there.

**`CurveEditor` `endpoints="pinned-both"` teleported.** The branch overwrote
the point with the range corner rather than its own coordinates, so the first
drag of a pinned endpoint sitting anywhere else snapped it to the corner and
committed. The existing test used endpoints already at the corners and could
not tell the two apart.

**Portal overlays were unmarked.** Consumers answer "did focus leave my
component?" with `closest('[data-weasel-overlay]')` — `apps/draw` does, to keep
a text-edit session alive while the user picks a font. Only `Select`'s popover
carried the marker. `ComboBox`, `Callout`, `Tooltip`, and `Dialog` now do, with
a test that fails when any of them loses it.

**`@weasel-js/hud`.** Detaching left the hovered widget painted as hovered and
holding `hovering = true`; because a re-attach starts with an empty hover
record, the widget also missed its next real `hover` emit. Detach now sends
`hoverleave`. `hovermove` fired only on the move that *entered* a widget, so
the `x`/`y` it carries were frozen for the rest of the hover — it now fires on
every move inside. The six widget factories pushed onto the list unconditionally
while `add()` refused on a detached HUD; both go through one guard. `Widget`
gained an optional `disposed` flag, which lets a loupe notice that its window
was removed through `hud.remove` and release its `pointermove` listener instead
of running a synchronous `readPixels` per mouse move forever; `aimAt` after
`dispose` is now a no-op.

## Found and deliberately not fixed

**Nested `<button>` in `Badge`.** `<Badge onClick={…} onRemove={…}>` renders the
remove button inside the badge's own `<button>` — invalid HTML and nested
interactive content. Fixing it means moving the remove control outside the
badge element, which relocates it outside the painted pill. That is a visual
decision, and the visual suite was off-limits in this run.

**`LayeredCurveEditor`'s `onLayerChange` / `onLayerCommit`.** `onLayerChange` is
the live channel, which inverts the package's meaning of `change`. The
`onInput`/`onChange` pass (917359a8) named the layer-gesture callbacks as
deliberately out of its scope, so this is a decision to revisit rather than a
defect to fix behind its author's back.

**`onInput` required, `onChange` optional in `CurveEditor` / `PointPlotter` /
`Slider`.** The inverse of `ColorField` and `GradientEditor`. Also settled in
917359a8: which callback is required follows each control's state model, not
its name.

**`hud.widgets()` returns the live internal array.** Typed `readonly Widget[]`,
but `add`/`remove` splice it and `attach.ts` iterates it twice per frame. A
copy is the correct return, and it is a per-frame allocation in the draw loop —
worth doing with a measurement rather than on a reading.

**`hud` `exports` lists `"import"` before `"types"`.** Condition order matters
and `"types"` should come first, but every package except `ui` has it this way.
It is a repo-wide manifest change, not a hud one.

**No keyboard path to any HUD widget.** The HUD paints into WebGL: its buttons
and window close boxes have no DOM node, no role, and no focus. Closing that is
a design project (mirroring the widget tree into the DOM), not a review fix.

**`CurveEditor` history gaps.** A click on an anchor with no movement pushes a
no-op undo entry and clears the redo stack, and right-click delete bypasses the
layer history entirely so one undo reverts two gestures. Both are real; both
need a decision about what `LayeredCurveEditor`'s history is supposed to
record, which is more than a review should settle.

**Inline styles.** Most are genuinely dynamic (CSS custom properties, computed
positions, a composed `background`). A handful are constants —
`display: 'contents'` in `CurveEditor`, `pointerEvents: 'none'` repeated eleven
times across `Badge/effects/` — and the `Badge` effects set `stopColor` /
`stopOpacity` through `style` where React accepts them as SVG attributes. All
cosmetic; none changed here, to keep the diff about behavior.

## Not verified

- Whether `ColorField` can lose an edit by unmounting while the native color
  picker is open. The commit-on-blur shape allows it; no concrete host sequence
  was found.
- `GradientEditor` labels swatches `Stop ${index + 1}` from the unsorted array
  while rendering them sorted, so a dragged stop may announce the wrong number.
  Cosmetic, and how a real consumer labels these was not established.
- Whether any in-tree contribution can preempt the eager `pointerDown` dispatch
  that `hud.drag` depends on. None was found, so the dependency stands
  undocumented but unbroken.
