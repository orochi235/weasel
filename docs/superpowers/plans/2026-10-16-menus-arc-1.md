# Menus arc 1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Anchor a menu to the rect of the control it hangs from, give consumers `useCommand` to turn a callback into a registered action, and finish the asset editor's handling of menu assets.

**Architecture:** Placement gains a rect anchor in `@weasel-js/menu`, carried on routing's `MenuOpenRequest`/`OpenMenu` and honored by both renderers. `useCommand` lives in routing beside `useAction` and is re-exported by core. The asset editor files menu assets under their own heading, stops treating a menu root as a holder of pages, and previews a menu root open.

**Tech Stack:** TypeScript, React 19, vitest (jsdom `weasel-ui` project, headless-Chromium `browser` project), npm workspaces, changesets.

**Spec:** `docs/superpowers/specs/2026-10-16-menus-as-layout-assets-design.md`. Arc 1 there is "the rect anchor, `useCommand`, and the rest of the asset editor". Its "Landed" section lists what the `surfaces` branch already built: `as: 'menu'`, `resolveSchemaMenu`, `MenuDef = { id, when?, menu }`, `BarMenu`, `GROUP_ICON.menu` and the `as` choices in `kindSchemas.ts`. In a form, a menu group draws as a panel (`prefAsBox` in `packages/prefs/src/groups.ts`); that is landed and deliberate, and this plan leaves it alone.

## Review Focus

- A title near the right edge of the viewport: its menu right-aligns to the title instead of clipping. Pinned in Task 1.
- A title near the bottom of the viewport: its menu opens above, with its bottom at the title's top, never over it. Pinned in Tasks 1 and 2.
- `useCommand` called with a new inline callback and a new inline options object every render: no re-registration. Pinned in Task 3.
- A command whose component unmounts: the action leaves the registry and a stale `trigger` does nothing. Pinned in Task 3.
- A bar holding menus and one ordinary cell is still a toolbar, not a menu bar, in the asset list. Pinned in Task 4.

### Task 3: `useCommand`

**Files:**
- Create: `packages/routing/src/interactions/actions/useCommand.ts`
- Modify: `packages/routing/src/react.ts` (export beside `useAction`, line 17)
- Modify: `packages/core/src/barrel/routing.ts` (re-export by name, line 8, and the `CommandOptions` type)
- Test: `packages/routing/src/interactions/actions/useCommand.test.tsx`

**Interfaces:**
- Produces, public (no `@experimental` tag on either):

```ts
export interface CommandOptions {
  /** True when the command can run, else why not. Read each time it is asked. */
  enabled?: () => true | ActionDisabledReason;
  /** Whether it reads as held down. Read each time it is asked. */
  active?: () => boolean;
  keys?: GestureSpec | readonly GestureSpec[];
  icon?: ReactNode | (() => ReactNode);
  tags?: readonly string[];
}
export function useCommand(id: string, label: string, run: () => void, options?: CommandOptions): void;
```

  It registers an `Action` with `invoker: { timing: 'immediate', run }` on the nearest `ActionsProvider` for the component's lifetime. It re-registers only when `id`, `label`, `keys` or `tags` change, comparing `keys` and `tags` by value. `run`, `enabled`, `active` and `icon` are read from a ref when used. `ActionDisabledReason` and `GestureSpec` are already public; if either turns out tagged `@experimental`, stop and ask before going on.

- [ ] **Step 1: Write the failing tests**, each rendered under `<ActionsProvider>` with a probe component that captures `useActionsRegistry()`:
  - `'registers an immediate action with the label'`: `useCommand('cmd.a', 'A', fn)`; `registry.list().find((a) => a.id === 'cmd.a')` has `label: 'A'` and `invoker.timing: 'immediate'`.
  - `'runs the latest callback'`: rerender with a second `vi.fn()`; `registry.trigger('cmd.a')` calls the second, not the first.
  - `'does not re-register for new inline callbacks and equal options'`: rerender with a new inline `run` and a new `{ keys: { kind: 'key', key: 'r' }, tags: ['x'] }` equal by value; the `Action` object found before and after is the same reference (`toBe`).
  - `'re-registers when the label changes'`: rerender with `'B'`; the found action's `label` is `'B'`.
  - `'asks enabled and active through the latest options'`: `enabled: () => ActionDisabledReason.NotApplicable`, `active: () => true`; `evaluateEnabled(action).enabled` is `false` and `evaluateActive(action)` is `true`.
  - `'leaves the registry on unmount'`: after `unmount()`, `registry.list()` holds no `cmd.a`, and `registry.trigger('cmd.a')` returns `false` without calling `run`.

- [ ] **Step 2: Commit the tests alone, run on the fleet, and watch them fail on the missing module**

- [ ] **Step 3: Implement `useCommand`** in `useCommand.ts`, on top of `useAction`. Pass `icon` as a thunk reading the ref only when an icon was given, so an action without one stays without one.
