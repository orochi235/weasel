# Menu bar and access letters Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A `MenuBar` component drawn from a bar of menu groups, access letters for menus and their rows, and `MenuButton` drawn by the context menu's renderer instead of React Aria's `Menu`.

**Architecture:** The headless model (`@weasel-js/menu`) learns access letters, links and an "edge" key effect; routing's resolver carries a declared letter from the schema onto entries; ui's DOM renderer (`OpenPanels`/`MenuPanel`/`MenuRow`) draws them. `MenuBar` (ui) and `MenuButton` (ui) both open menus through `OpenPanels`, so one controller runs every DOM menu. F10 and the access chords run on a no-canvas, `keyboard: 'first'` dispatcher owned by the bar.

**Tech Stack:** TypeScript, React 19, vitest (jsdom `weasel-ui`/`core` projects, headless Chromium `browser` project).

**Spec:** `docs/superpowers/specs/2026-10-16-menus-as-layout-assets-design.md` — sections "Renderer and placement", "The menu bar", "Access letters"; Order item 1.

## Review Focus

- **A declared letter absent from the label.** `access: 'x'` on "File": the letter still works; nothing is underlined and nothing crashes. Test in Task 3.
- **Two rows declaring the same letter in one menu.** The first in order wins, the same as a key repeated cycles nowhere. Test in Task 1.
- **A disabled row's letter.** Pressing it does nothing and does not fall through to typeahead. Test in Task 1.
- **A press that starts on a title and ends off any row.** The menu stays open, nothing runs. Test in Task 5.
- **An app key binding identical to an access chord.** It must not fire as well as the menu opening, and no app binding fires twice because the bar runs a second dispatcher. Test in Task 6.

### Task 5: `MenuBar` — titles, pointer and keyboard inside the bar

**Files:**
- Create: `packages/ui/src/components/MenuBar/MenuBar.tsx`, `MenuBar.module.css`, `index.ts`, `menuBarTitles.ts`, `MenuBar.test.tsx`, `MenuBar.browser.test.tsx`, `MenuBar.stories.tsx`
- Modify: `packages/ui/src/index.ts` (export `MenuBar`, `MenuBarProps`)

**Interfaces:**
- Consumes: `OpenPanels` with `inside`, `onEdge`, `releaseRuns` (Task 3); `resolveSchemaMenu`, `barMenuRoot` (existing); `AccessLabel` (Task 3).
- Produces:
  - `menuBarTitles(schema: PrefGroup): ({ kind: 'menu'; key: string; name: string; access?: string; group: PrefGroup } | { kind: 'other'; key: string; schema: PrefGroup })[]` — top-level children in order; each `as: 'menu'` group a title; each consecutive run of anything else one `other` holding those children as a group.
  - `MenuBarProps` = `{ schema: PrefGroup; over?: PrefGroup; values?: Readonly<Record<string, unknown>>; onChange?: (path: string, value: unknown) => void; label?: string /* aria-label, default 'Menu bar' */; accessChord?: MenuAccessChord; className?: string }`, where `MenuAccessChord = { alt?: boolean; ctrl?: boolean; meta?: boolean; shift?: boolean }` (default `{ alt: true }`; used in Task 6).
  - `MenuBar` renders `role="menubar"`; each title a `<button role="menuitem" aria-haspopup="menu" aria-expanded>` with `AccessLabel`; an `other` run as `<Bar schema={run} over values onChange />`. Titles rove: one has `tabIndex=0`. Menus resolve exactly as `BarMenu` does (`barMenuRoot(group, key)` through `resolveSchemaMenu` with the bar's `values`/`onChange`/`over`), opened `under` the title's rect.
  - An imperative handle for Task 6: `MenuBarHandle = { focus(): void; open(key: string): void }` via `forwardRef`/`ref` prop, or an internal context the key layer reads — implementer's choice, internal only.

Behavior (spec "The menu bar"):
- Pointer: `pointerdown` on a closed title opens it (source `pointer`) and arms `releaseRuns`; `pointerdown` on the open title closes it; with a menu open, `pointerenter` on another title switches to it; release over a row runs it; titles count as `inside` so the panel's dismiss does not fire on them.
- Keyboard on a focused title: Left/Right move focus between titles (wrapping); Down, Enter or Space opens with the first row highlighted.
- Inside a menu: `onEdge(dir)` opens the neighboring title's menu, keyboard-sourced; Escape closes and focuses its title (the controller's close + `close` returning focus to the title); Escape on a focused title with no menu open gives focus back to the element focused before the bar was entered (remembered on focus-in from outside), else blurs.
