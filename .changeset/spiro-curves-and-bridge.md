Spiro curves: a curve drawn by its on-curve points alone. `@weasel-js/geom` solves one with `solveSpiro(points, closed)`: an Euler-spiral segment, whose curvature changes evenly along it, runs between each pair of points, and the segments are solved together so tangent and curvature carry straight through every `smooth` point. A `corner` lets its two sides turn independently, `left` continues the straight segment arriving at it, and `right` runs the curve into the straight segment leaving it. `spiroToPath(contours)` writes the solved curve as cubics, splitting a segment wherever one cubic would stray more than a ten-thousandth of its length, and reports which anchor each point became; `spiroContoursOf`, `spiroControlPath` and `spiroContoursFromControl` read the points back out of such a path and in from an edited control path. The `spiro` curve representation in `@weasel-js/geom/curves` now uses the solver.

Breaking: `SharedAnchor.spiroType` takes a `SpiroKind` (`'smooth' | 'corner' | 'left' | 'right'`) where it took `'g2-smooth' | 'g4-smooth' | 'corner'`. G4 points were never solved as such.

`@weasel-js/core` stores a spiro curve on a path node as `data.path` plus `data.spiro` (`spiroNodeData`, `spiroOf`, `withoutSpiro`). Path edit edits such a node's points through its straight-sided control path: `getEditablePath` returns that path, and every edit solves the curve again, the live drag preview included. The new spiro tool (`useSpiroTool`, built-in tool id `spiro`, key `B`) places points by clicking, each of the kind its `spiro.placePoint` action's `params.kind` names, Alt-click for a corner, and inserts the curve through the `insert` dep as kind `'spiro'`. `setSpiroKind` sets the kind of the points selected in path edit, and `releaseSpiro` ("Convert to path") turns a spiro curve into an ordinary path. In path edit each point draws by its kind (`anchorMarkerPath`): a circle for smooth, a square for a corner, a half-disc facing away from the line for `left` and `right`. Dragging the curve between two points adds a smooth point there and drags it; the segment affordance hit-tests the curve itself, which the `editAnchors` dep's new optional `getOutlinePath` supplies. Path commands that rewrite a node's geometry, such as Join and Simplify, leave plain geometry.

Bridge: `bridgePaths` (Mod+Shift+J) joins the nearest open ends of one or two selected paths with a curve that leaves each end along the direction its path was heading, each handle `params.tension` times the gap long (default `DEFAULT_BRIDGE_TENSION`, 0.4), as one undo step; two paths become one. `bridgeAnchors` does the same for the two end anchors selected in path edit. Underneath, `joinSubpathEnds` and `joinAnchorsAt` take a `JoinOptions` with that `tension`. All four commands are in the standard actions and the `paths` feature preset.
