## What's next: wire the seam into @weasel-js/text

Bidi exists and is correct; **nothing uses it yet.** RTL text still lays out in
logical order. That wiring is the remaining work:

1. Declare `BidiResolver` in `packages/text` — structurally identical to
   `BidiEngine` in `packages/bidi/src/index.ts`, but **declared, not imported**.
   Neither package may depend on the other; that is the whole design. `bidi`
   goes in text's `devDependencies` only, for the end-to-end test.
2. `bidi?: BidiResolver` on `LayoutRunsOpts`. Absent means today's behavior.
3. Reorder per line in `layoutRuns`, after the wrap. `cells` stays in **logical**
   order — that is settled, because klieg indexes `cells[i]` as slot `i` and the
   contract already shipped. What changes is that `cell.x` stops being
   monotonic. Visual order is derivable by sorting on `x`.
4. `hitTest.ts` currently assumes monotonic `x` (`cells[i+1].x` is the next
   boundary). It must find the cell whose extent contains the point instead,
   which needs an `advance` on `LaidOutCell` — add it.
5. L4 mirroring at paint, against each cell's resolved level.
6. Warn once when `direction: 'rtl'` or strong RTL text is present and no
   resolver was passed, using the existing `warnMissingGlyphOnce` pattern in
   `layoutRuns.ts`. Silent logical-order RTL is the footgun this design has.

**The kerning rule to use** (worked out, not yet implemented): walk the visual
order; between visually adjacent cells `prev` and `cur`, the gap is
`entries[cur].kerningBefore` when `cur === prev + 1`, `entries[prev].kerningBefore`
when `prev === cur + 1`, and zero otherwise. That places kerning correctly in
both directions and drops it across a bidi boundary, which is where it should
not apply anyway.

## Blocked, and not ours to unblock

`@weasel-js/text` and `@weasel-js/paint` are **not on npm** — the only two of 15
missing, now 16 with `bidi`. Not a config problem: both are `access: public`,
in the changesets `fixed` group, identical to the ones that shipped. They were
created after 1.2.0 published, and the Version Packages PR **#24 has been open
since Aug 24**, so nothing has published since. In-tree `core` depends on both,
so core cannot ship again without them.

Merging #24 is the fix and it is **Mike's call — he has not made it.** One risk:
the release publishes via OIDC trusted publishing, configured per-package on
npmjs.com, so a brand-new package (`bidi` included) may need one manual first
publish to bootstrap. Unverified.

A second Claude session (`klieg-d1`) is building klieg against the cells API and
is blocked purely on that merge plus this branch.

## Decisions made in conversation, not visible in the code

- **Full UAX #9 over pure-RTL reversal**, chosen explicitly against the cheaper
  option, because reversal-only renders embedded Latin and digits backwards and
  gets replaced rather than extended. Don't re-propose it.
- **Arabic shaping is deliberately out**, recorded as a P3 in `docs/TODO.md`.
  Bidi gives correct Hebrew and still-unjoined Arabic.
- **Vertical writing modes** are a P3 too, written around the inline/block axis
  refactor they imply rather than the scripts.
- **bidi is its own package rather than living in `text`**, so a consumer who
  renders no RTL never installs the Unicode tables. The tarball is 31 kB and
  excludes the 1.7 MB of conformance fixtures.
